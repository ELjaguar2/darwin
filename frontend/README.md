# Darwin frontend (lots L8 to L19)

All visible text is in English (lot L19). Content generated by the API and historical logs (letters, pitches, deliverables of runs 5 to 9b) stays as recorded: the old runs are in French, the page "chrome" around them is in English. Protocol values returned by the API are never changed; the frontend maps them to English labels (see "Protocol values" below).

## L17 interface (default): three tabs

Clean, dark by default (light/dark toggle), large fonts, one main action per page. **The mode is always shown** in the header (MOCK, NEAR TESTNET or REPLAY); in replay, a banner "Replay of a real testnet run from <date>" (date formatted in English, e.g. "November 10, 2026") carries the progress and the x1/x5/x20 buttons (POST `/api/replay/speed`, no effect if the admin token is required).

| Tab | Content |
|---|---|
| **Mission** | living agents as cards (avatar colored by genome, first name, profession icon, balance gauge = balance / reproduction threshold); "Describe your mission…" bar (profession guessed from the text and minimum budget from the catalogue, editable with one click, Enter sends); live feed: mission, bids (price + pitch), award, work, deliverable (SVG as `<img data:>`, Markdown as DOM nodes), judge verdict, "paid ✓" + "proof ↗" nearblocks link. The card of the agent speaking lights up; births and deaths as fading notifications. Finished missions collapse. In replay: bar disabled ("Missions disabled during replay"), the feed replays the missions of the log. |
| **Lineage** | full-screen tree (wheel/pinch/button zoom, pan, recenter), nodes colored by profession, dead ones grayed; click = side panel (genome, personality, parent-child letters, financial history with balance curve); Escape closes. |
| **Proof** | indicators, population by generation (alive/dead per profession), money flows (earned, brain, passed, per generation), transactions with nearblocks links, TEE badge (honest: on-demand check, calls on attestable models counted), NEAR building blocks used. |

Old interface (L16): **`/?classique`** (the backend must redirect `/classique` to `/?classique`; the fake server already does). The URL keeps its historical name; the label is "classic" in English ("Classic interface"). The replay banner is kept there.

Hash routes keep their historical identifiers (`#/mission`, `#/lignees`, `#/preuves`) so that existing links keep working; only the visible labels are English (Mission / Lineage / Proof).

L17 files: `index.html` + `l17.css` (shell), `boot.js` (picks L17 or classic), `core.js` (state, full paginated history, SSE with resume, mode, financial ledger), `darwin.js` (routing, mode, notifications), `mission.js`, `lignees.js`, `preuves.js`, `jobs.js` (professions, icons, avatars; the historical writer/analyst/coder/summarizer/translator professions of runs 5 to 8 are readable), `chat-deliverable.js`, `classique-markup.js` (static markup of the old page, imported through DOMParser, never innerHTML). Compatible with the backend CSP (no inline script or `style=`).

Accepted degradations: the real log does not always contain the pitch of a bid (neutral summary: delay and profession, nothing invented) nor the content of deliverables (file list + "Deliverable not stored in the log"); without `population.snapshot`, the population is computed from the agent list.

## Protocol values (API) and their English display

The API badge values are English since L19; the frontend maps them (and the former French values, kept for old flows) to display labels through a lookup table in `format.js` (`BADGE_LABEL`, `badgeText`) and falls back to the raw value when unknown.

| API value | Displayed |
|---|---|
| `badge: "simulated"` (legacy `"simulé"`) | simulated |
| `badge: "subcontracting"` (legacy `"sous-traitance"`) | subcontract |
| `badge: "Visitor (funded by the demo account)"` (legacy `"Visiteur (financé par le compte de démo)"`) | Visitor (funded by the demo account) |
| `requester.label: "visiteur"` | visitor |
| task `status` (`posted`, `awarded`, `submitted`, `settled`, `rejected`, `expired`) | bidding, awarded, delivered, paid, refunded, expired |
| `chain.tx` `kind` (`create_account`, `transfer`, ...) | Birth (account created), Transfer, Escrow locked, ... |
| `balance.changed` `reason` (`birth`, `task`, `brain`, ...) | Birth capital, Mission paid, AI brain paid, ... |

Values kept as sent (not translated): validator ids such as `rule:non-vide-et-pertinent`, model names, account ids, hashes, and everything produced by agents and judges.

Check: `NODE_PATH=<node_modules with playwright> node frontend/dev/l17.cjs docs/captures` (46 checks against the fake server: tabs, mode, cards, bar, full feed up to "paid ✓", inert SVG deliverable, tree, zoom, panel, proof, classic, mobile 375, no console/CSP error). Against a replay backend: `REAL_URL=http://127.0.0.1:3000 node frontend/dev/l17.cjs <folder> --replay`. `l16.cjs` and `e2e.cjs` test the old interface through `/?classique`.

# Classic interface (lots L8, L16)

Single page, HTML + CSS + ES modules, **no build, no dependency, offline** (no external resource; compatible with the backend CSP: no inline script or `style=`). The backend (`backend/`) serves it statically.

## Run

| Need | Command | Expected |
|---|---|---|
| With the real backend (mock) | `npm run start:mock` then http://127.0.0.1:3000 | tree, balances, flows live |
| Quick demo | `DARWIN_PRESET=demo npm run start:mock` | 3 generations in a few minutes |
| Without backend | `node frontend/dev/fake-server.mjs` (port 3000, options at the top of the file) | fake log conforming to the catalogue (English test data) |
| End-to-end tests | `NODE_PATH=<node_modules with playwright> node frontend/dev/e2e.cjs <folder>` | 29 checks, screenshots |
| Against the real backend | `REAL_URL=http://127.0.0.1:3000 NODE_PATH=... node frontend/dev/real.cjs <folder>` | real form + rendering |

Fake server options: `--tick=400`, `--testnet` (real-looking hashes and explorer links), `--degraded`, `--no-sim`, `--task-status=429|503|400` (forces the response of `POST /api/tasks`). It is a test data generator, with no product logic.

## Files

`index.html` (structure), `style.css` (light/dark themes, variables), `freelance.css` (L16: specialization, market, lifecycle, deliverables), `deliverable.js` (safe deliverable rendering: minimal Markdown, SVG as `<img>`), `app.js` (loading, SSE with resume, panels, form), `store.js` (state rebuilt from the log), `tree.js` (animated SVG tree), `format.js` (amounts, links, safe DOM builder, protocol-value mapping), `theme-init.js` (theme before the first render), `screens/` (reference screenshots), `dev/` (development tools, not served by the fake server).

## Real freelance (lot L16)

- **Form**: 6 professions (logo, financial analysis, architecture, marketing, translation, legal checklist). Labels and floor prices come from `GET /api/catalogue`; the budget is pre-filled to the profession minimum; the "Budget too low" message is local (exact yocto comparison) and readable; warning "This is not legal advice" (legal) and reminder "the logo is original" (logo). Fallback if `/api/catalogue` answers 404: local labels, no price or rubric, the server applies its bounds.
- **Task** (panel "Task market", expand a task): 6-step lifecycle (posted, bidding, awarded, delivered, validated, paid or refunded) with clickable transactions, then the deliverable loaded on opening via `GET /api/tasks/:id/deliverable`: verdict badge, score and threshold, production and judge costs, scoring rubric, files with a Download button (`?download=1`).
- **Deliverable security**: text and Markdown = DOM nodes (never `innerHTML`, no link activated); **SVG only through `<img src="data:image/svg+xml,...">`** (no script executed, never injected); Mermaid: **source shown as code, no rendering** (the backend CSP, `script-src 'self'`, forbids cdnjs; the CSP is not weakened for display comfort).
- **Market panel**: active demand events (×3 or ×0.3, ticks left, up/down color) and history (replayed `market.event` events), floor price per profession.
- **Specialization panel**: from `population.snapshot` (latest snapshot via `/api/state`, field `populationSnapshot`, or event), one stacked bar per generation, one color and label per profession, alt text per row; HTML/CSS, no dependency.
- **Tree**: node color and letter = profession; legend of the 6 professions.
- **Check**: `NODE_PATH=<node_modules with playwright> node frontend/dev/l16.cjs <folder>` (32 checks against the fake server, which serves catalogue, trapped deliverables and snapshots; option `--no-catalogue` to test the 404 fallback). The fake server deliberately places a `<script>` and an `onerror` in an SVG and a Markdown file to prove they stay inert.

## What the page shows

- **Living tree**: birth from the parent (rings, edge drawn progressively), death (gray crossed node), size = balance, ring = lineage, letter = profession; floating gains/costs; "Lineages" panel (thriving / fragile / extinct); **generation counter**.
- Live **balances**, **transaction stream** (`testnet.nearblocks.io/txns/<hash>` link if `explorerUrl` is provided, or `near` chain; "mock" badge and no link for fictitious hashes; per-tick living costs hidden by default), **chronicle**, **market** (tasks, bids, "validated by: ..."), parent -> child **letters** and agent profile.
- **"Post a task" form**: `POST /api/tasks`; handles 201, 400 (server messages), 429 and 503 with `Retry-After` (button locked; `VALIDATION_PENDING` shown as waiting, not outage), 413, 415, 403.
- **Honesty (D-024, R8)**: MOCK MODE, "simulated" client, "Visitor (funded by the demo account)", "Degraded escrow" (if `/api/health.escrow = "operator-account"`, independent of the mock badge), trust model, NEAR tools (RPC, contract, NEAR AI Cloud, Intents) with real / simulated state.
- **Connection**: Live / Reconnecting (attempt n) / Offline dot; resume through `?since=<lastSeq>`; `reset` event = clear then replay.
- **Accessibility**: contrast checked visually in both themes, `aria-label`, keyboard-scrollable regions, visible focus, `prefers-reduced-motion` (instant positions, effects removed), no horizontal scroll from 320 px, never `innerHTML`.

## API contract used (aligned with `backend/app.ts`)

`GET /api/state` (`SimState`) then `EventSource("/api/stream?since=" + lastSeq)` with one `addEventListener` per catalogue type + `reset`; `GET /api/events?since=&limit=` (`{events, lastSeq}`, to seed the transaction stream); `GET /api/health` (`escrow`, `mock`, `chain`/`brain` objects); `GET /api/letters/:id` (`{letter}`); `POST /api/tasks`. Tasks carry `badge` and `validatedBy`. Errors have the shape `{error:{code,message,retryable?}}` (zod `issues` are also read).
